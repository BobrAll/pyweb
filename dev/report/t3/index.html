    Т3. Обзор отечественных CI/CD-сервисов и статических хостингов¶

    Введение¶

    В рамках данного исследования проведён сравнительный анализ трёх отечественных платформ CI/CD — GitVerse, SourceCraft и GitFlic — и трёх вариантов размещения статических сайтов: Helios ИТМО, Yandex Object Storage и VK Cloud / Selectel / Timeweb / Cloud.ru. Цель — оценить пригодность этих сервисов для автоматизированной публикации результатов экспериментов и определить трудозатраты миграции существующего GitHub Actions workflow на выбранную платформу.

    Обоснование критериев сравнения¶

    Критерии определены исходя из задачи публикации статического сайта с CI/CD-пайплайном. Каждый критерий оценён по шкале от 1 до 5, где 5 — наиболее важный для данной задачи.

    Критерии с весом 5 (критически важные)¶

    • Синтаксис пайплайна и совместимость с GitHub Actions: определяет трудозатраты миграции существующего workflow. Чем выше совместимость, тем меньше переписывания.
    • Способ доставки файлов: для статического хостинга критично наличие S3 API, SSH/rsync или git push. От этого зависит, как именно CI/CD будет публиковать сайт.

    Критерии с весом 4¶

    • Модель раннеров: облачные (managed) или self-hosted. Влияет на требования к инфраструктуре.
    • Работа с секретами, артефактами и кэшем: без этого невозможно воспроизводимое CI/CD.
    • Лимиты бесплатного тарифа: для лабораторной работы важно, чтобы бесплатного лимита хватало.
    • Поддержка собственного домена и HTTPS: для публикации результатов на своём домене.

    Критерии с весом 3¶

    • Наличие каталога готовых действий: ускоряет разработку пайплайна.
    • Доступность сервиса и качество документации: влияет на скорость отладки.
    • Способ доставки файлов: git push, S3 API, SSH, WebDAV, FTP.

    Детальный анализ¶

    GitVerse¶

    GitVerse — российская платформа от Сбера, наиболее близкая по синтаксису к GitHub Actions. Раннер построен на базе act, что позволяет переиспользовать большинство существующих actions из GitHub Marketplace. Облачные раннеры предоставляют эфемерную среду на базе ubuntu-latest с лимитом 1000 минут в месяц для публичных репозиториев. Доступны также self-hosted раннеры с настраиваемым параллелизмом.

    Преимущества: максимальная совместимость с GitHub Actions, обширная документация, активное сообщество, бесплатный тариф для образовательных проектов.

    Ограничения: отсутствует доступ к docker.sock на облачных раннерах (используется kaniko), CI/CD недоступен для зеркальных репозиториев.

    SourceCraft¶

    SourceCraft — платформа от Яндекса с поддержкой облачных, serverless и self-hosted воркеров. Конфигурация хранится в .sourcecraft/ci.yaml. Поддерживается запуск GitHub Actions, но только на облачных воркерах. Лимит бесплатного тарифа — 1000 минут в месяц. Для образовательных и open-source проектов возможно увеличение квоты по запросу в поддержку.

    Преимущества: serverless-воркеры с быстрым запуском, интеграция с Yandex Cloud, автоматическое преобразование GitHub Actions в формат SourceCraft.

    Ограничения: свой синтаксис YAML (отличается от GitHub Actions), совместимость с GitHub Actions только на облачных воркерах, отсутствие каталога готовых действий.

    GitFlic¶

    GitFlic — платформа от ГК «Астра» с синтаксисом, близким к GitLab CI (gitflic-ci.yaml). Поддерживаются стадии, job, кэш, артефакты, переменные, parallel:matrix. Бесплатный тариф: до 5 участников, 4 ГБ на репозиторий.

    Преимущества: знакомый синтаксис для тех, кто работал с GitLab CI, поддержка self-hosted Kubernetes-агентов.

    Ограничения: синтаксис несовместим с GitHub Actions, требуется переписывание workflow с нуля.

    Helios ИТМО¶

    Helios — учебный сервер ИТМО, предоставляющий студентам SSH-доступ и возможность размещения статических сайтов в ~/public_html/. Доступ осуществляется по SSH (порт 2222), деплой — через rsync или scp. Сайт доступен по адресу https://se.ifmo.ru/~<username>/.

    Преимущества: бесплатно для студентов ИТМО, полный контроль над файловой системой, поддержка HTTPS.

    Ограничения: ограниченные ресурсы, отсутствие S3 API, необходимость ручной настройки прав доступа.

    Yandex Object Storage¶

    Yandex Object Storage поддерживает хостинг статических сайтов через включение режима «Веб-сайт» в настройках бакета. Управление — через консоль, CLI, Terraform или S3 API. Поддерживается собственный домен и HTTPS.

    Преимущества: полностью управляемый сервис, высокая надёжность, интеграция с Yandex Cloud CDN.

    Ограничения: платный (есть пробный период), требуется настройка публичного доступа к бакету.

    VK Cloud / Selectel / Timeweb¶

    Все три провайдера предоставляют S3-совместимое объектное хранилище с поддержкой хостинга статических сайтов. Управление — через консоль и S3 API. У Selectel и VK Cloud есть поддержка собственного домена; у Timeweb на момент написания собственным доменом подключить нельзя.

    Преимущества: совместимость с S3 API, простота настройки, конкурентоспособные цены.

    Ограничения: платные (есть free tier у Cloud.ru), ограничения по исходящему трафику.

    Оценка трудозатрат миграции GitHub Actions workflow¶

    На GitVerse¶

    Переносится без изменений: структура YAML, on:, jobs:, runs-on:, steps:, uses: (большинство actions из Marketplace), env:, with:, if:.

    Требует изменений: экшены, специфичные для GitHub Pages (actions/upload-pages-artifact, actions/deploy-pages) — нужно заменить на GitVerse-аналоги (actions/upload-pages-artifact@v1, actions/deploy-pages@v1) или на git push в ветку.

    Не поддерживается: docker.sock на облачных раннерах (замена на kaniko).

    Итог: миграция минимальная. Большая часть workflow работает без изменений.

    На SourceCraft¶

    Переносится без изменений: on:, jobs:, steps:, script:, uses: (GitHub Actions на облачных воркерах).

    Требует изменений: конфигурация хранится в .sourcecraft/ci.yaml, а не в .github/workflows/. Структура YAML отличается: используются workflows, tasks, cubes. Экшены для деплоя — свои.

    Не поддерживается: GitHub Actions на serverless-воркерах и self-hosted.

    Итог: требуется переписывание конфигурации под новый синтаксис, но логика стадий сохраняется.

    На GitFlic¶

    Переносится без изменений: stages, script, variables, cache, artifacts, needs (синтаксис похож на GitLab CI).

    Требует изменений: весь workflow переписывается с GitHub Actions на синтаксис gitflic-ci.yaml. Конфигурация хранится в отдельном файле. Экшены не поддерживаются — только shell-скрипты.

    Не поддерживается: uses: (готовые actions), GitHub-специфичные контексты (github.*).

    Итог: максимальные трудозатраты. Workflow нужно переписывать с нуля.

    Вывод¶

    Оптимальная связка для публикации результатов экспериментов¶

    GitVerse + Helios ИТМО является оптимальной связкой для задачи публикации результатов экспериментов, поскольку:

    1. Минимальные трудозатраты миграции: синтаксис GitVerse совместим с GitHub Actions. Существующий workflow переносится практически без изменений — достаточно заменить экшены деплоя на GitVerse-аналоги.
    2. Бесплатный тариф: 1000 минут сборочного времени в месяц для публичных репозиториев — достаточно для лабораторной работы.
    3. Полный контроль над хостингом: Helios предоставляет SSH-доступ, что позволяет использовать rsync для деплоя и настраивать healthcheck после публикации.
    4. Интеграция с существующим стеком: GitVerse поддерживает actions/upload-pages-artifact и actions/deploy-pages (в собственной реализации), что упрощает переход с GitHub Pages.

    Условия, при которых вывод меняется¶

    1. Если требуется serverless-инфраструктура: SourceCraft может быть предпочтительнее за счёт быстрого запуска serverless-воркеров и интеграции с Yandex Cloud.
    2. Если команда уже использует GitLab CI: GitFlic будет удобнее за счёт знакомого синтаксиса, но потребует полного переписывания workflow.
    3. Если нет доступа к Helios ИТМО: Yandex Object Storage или VK Cloud предоставляют S3-совместимый хостинг с поддержкой собственного домена и HTTPS. Деплой через S3 API также автоматизируется в CI/CD.
    4. Если критична скорость запуска CI: SourceCraft с serverless-воркерами запускается быстрее, чем облачные раннеры GitVerse.
