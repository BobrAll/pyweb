    Т1. Сравнительный анализ генераторов статических сайтов¶

    Введение¶

    В рамках данного исследования проведён сравнительный анализ четырёх генераторов статических сайтов (SSG) на Python: MkDocs (с темой Material), Sphinx (с MyST-Parser), Pelican и Quarto. Цель — определить оптимальный инструмент для публикации результатов экспериментов и сопровождающих их исследовательских материалов.

    Обоснование весов критериев¶

    Веса критериев определены исходя из задачи публикации результатов экспериментов. Каждый критерий оценён по шкале от 1 до 5, где 5 — наиболее важный для данной задачи.

    Критерии с весом 5 (критически важные)¶

    • Формулы LaTeX: обязательны для публикации математических результатов. Требуется поддержка нумерации, ссылок на уравнения и окружений amsmath.
    • Библиография (BibTeX): научные публикации требуют цитирования источников с автоматическим формированием списка литературы.
    • Исполняемый контент: возможность запускать ноутбуки/скрипты при сборке критична для воспроизводимости результатов (см. задание Р3).

    Критерии с весом 4¶

    • Рисунки: подписи, автонумерация, перекрёстные ссылки.
    • Таблицы: объединение ячеек, генерация из CSV/DataFrame.
    • Версионирование документации: необходимо для отслеживания версий результатов (см. задание Р5).
    • Локальный поиск: качество поиска по русскоязычным запросам.

    Критерии с весом 3¶

    • Формат исходников: Markdown, reStructuredText, MyST, .ipynb, .qmd.
    • Интерактивные визуализации: Plotly, Bokeh, Altair.
    • Многоколоночная вёрстка: grid, cards, columns.
    • Экспорт в PDF/LaTeX: единый источник — несколько представлений.
    • Зрелость проекта: лицензия, активность разработки.

    Критерии с весом 2¶

    • Локализация (i18n): менее критична, но полезна.
    • Автодокументирование кода: нужно, если публикуется код эксперимента.
    • Расширяемость: плагины, хуки, директивы.
    • Время сборки: холодной и инкрементальной.
    • Доступность через зеркала PyPI: важно для воспроизводимости в РФ.

    Детальный анализ по группам критериев¶

    1. Представление научного контента¶

    MkDocs + Material демонстрирует отличную поддержку формул LaTeX через pymdownx.arithmatex. Нумерация и ссылки на уравнения реализуются через MathJax с tags: 'ams'. Библиография подключается через mkdocs-bibtex. Однако объединение ячеек в таблицах требует raw HTML, а интерактивные визуализации — установки mkdocs-plotly-plugin.

    Sphinx + MyST показывает наилучшие результаты для научного контента. MyST поддерживает прямые amsmath-окружения, sphinxcontrib-bibtex обеспечивает полноценную работу с BibTeX, а MyST-NB позволяет исполнять ноутбуки при сборке. Таблицы с объединением ячеек реализуются через grid tables или sphinx-excel.

    Pelican требует значительных усилий для научного контента. Математика подключается через pelican-render-math, библиография — через pelican-bibtex. Исполняемый контент не поддерживается.

    Quarto — специализированный инструмент для научных публикаций. Встроенная поддержка формул, библиографии, исполняемого кода и интерактивных визуализаций делает его лидером по этой группе критериев.

    2. Вёрстка и шаблоны¶

    Material for MkDocs предоставляет grid cards для многоколоночной вёрстки и систему theme overrides для кастомизации. Sphinx использует sphinx-design для grid-вёрстки. Quarto имеет встроенную поддержку columns.

    3. Эксплуатационные характеристики¶

    Версионирование документации: MkDocs использует mike, Sphinx — sphinx-multiversion. Pelican не имеет встроенного решения. Quarto требует ручной настройки.

    Локальный поиск: MkDocs и Sphinx имеют встроенный поиск с поддержкой русского языка. Pelican требует плагинов. Quarto имеет встроенный поиск.

    Вывод¶

    Оптимальный генератор для задачи публикации результатов экспериментов¶

    Sphinx с MyST-Parser является оптимальным выбором для публикации результатов экспериментов, поскольку:

    1. Наилучшая поддержка научного контента: формулы LaTeX с amsmath, полноценная библиография через sphinxcontrib-bibtex, таблицы с объединением ячеек, исполняемые ноутбуки через MyST-NB.
    2. Встроенное версионирование: sphinx-multiversion позволяет публиковать версии результатов.
    3. Автодокументирование кода: autodoc извлекает документацию из docstrings.
    4. Экспорт в PDF/LaTeX: встроенные билдеры для множественных представлений.
    5. Зрелость и поддержка: активное сообщество, обширная документация, доступность через PyPI.

    Условия, при которых вывод меняется¶

    1. Если требуется интерактивный контент с Plotly: Quarto может быть предпочтительнее, так как имеет встроенную поддержку интерактивных визуализаций без плагинов.

    2. Если важна скорость сборки и простота: MkDocs + Material быстрее настраивается и собирается, подходит для небольших сайтов с базовыми формулами.

    3. Если публикуется только блог без сложной математики: Pelican достаточен, но требует больше ручной работы для научного контента.

    4. Если требуется тесная интеграция с Jupyter-ноутбуками: Quarto или Jupyter Book (на базе Sphinx) — лучший выбор.
